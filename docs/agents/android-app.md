# Android app-only behaviour

Part of the INPX Library Server agent spec. The rules every task must obey are in
[`AGENTS.md`](../../AGENTS.md); this file is the detailed reference of one subsystem.
Read it before changing that area and update it in the same commit as the code.

Scope: features that exist only in `inpx-book-reader` and need no server change

---

- Download format in the Android app: the app follows the account `downloadFormat` only for formats its reader opens (`epub2` / `epub3` / `kepub` → saved as `.epub`, `fb2zip` → saved as `.fb2.zip` and read as FBZ with the exact FB2 position, from `GET /download/:id?format=` (`/download/b64/<ref>`)), and only when the book's `downloadFormats` (catalog lists, additive in `/api/books/:id/meta`) offer it; otherwise (`''`, `kfx`, `azw8`, `azw3`, non-FB2 books) it keeps downloading `/api/books/:id/content`. Settable in Profile → Хранилище «Формат скачивания» (Исходный / EPUB / EPUB3 / FB2.ZIP = the same server preference). The app also opens `.fb2.zip` / `.fbz` / a bare `.zip` handed over by other apps («Открыть с помощью»; app-only, no server API). A converted EPUB and the web FB2 share the position only by fraction: `positionForBookFormat` (`public/position-sync.js`) drops the CFI / `fb2Href` / section-offset anchor / page of a position saved in the other format (FB2 = `fb2Href` without CFI, EPUB = `epubcfi(…)`) — both readers call it before restoring (Foliate failed on `goTo('0#2')` in an EPUB)
- Android account switching (app-only; the web keeps its normal login): Profile → «Сменить» lists saved accounts (non-secret list in localStorage, device tokens per account in the Keystore via `SecureCredentials.saveAccount`). Downloaded books are shared; positions, bookmarks, notes, shelves, favorites, sync queue and reader data belong to one account: the live set sits in the regular tables, other accounts' sets are IndexedDB snapshots swapped on switch (then reload). `inpx_personal_owner` names the owner; the sync queue and background sync never push it under another account, and «Выйти» → login as somebody else swaps first. No server API
- Android home / lock-screen widgets (current book, read-aloud remote with sleep timer, «Новое у любимых» covers) are app-only: they use existing routes (`/api/library/following`, `siteName` / `logoUrl` / `showLogo` from `/api/settings/ui` for the library name and logo at the top of each widget) and the app's cover cache, no server API. Lock-screen placement works only where Android allows it (`widgetCategory` `keyguard`: tablet hub, Android 15–16). Details in the reader's `AGENTS.md` («Виджеты»)
- Android home blocks «Скачанные» / «Папки» (books and library folders on the device) are app-only and device-only: a local switch, not part of the account `homeLayout`, the server never sees them. The «Скачанные» tab shows the books as folders, the way they lie in the library folder (Author/Series/file), built from the downloaded books alone (no server API). Details in the reader's `AGENTS.md`
- Android books already in the library folder (app-only): after a reinstall the app finds its downloaded files again by the book id in the file name and registers them instead of downloading twice (asks once for Android «All files access», needed on Android 11+ to see the old files in Download/); Profile → Хранилище also offers «Найти» and removing the «name (N)» copies left by earlier reinstalls. No server API (server ids of an old source are matched by `/api/books/resolve`). Details in the reader's `AGENTS.md`
- Android BOOX sleep screen (app-only, Onyx with Android 10+): Profile → Внешний вид «Обложка на экране сна» draws the current book's cover (+ title, author, series, progress) into `Pictures/` and points the BOOX screensaver at it with the `onyx.action.SCREENSAVER` broadcast; a device setting, not per account. No server API. Details in the reader's `AGENTS.md`
- Android «Домашний экран» (launcher mode for e-readers such as BOOX) is app-only: Profile → Внешний вид turns on a hidden HOME trampoline activity, and while the app is the default home its Home tab is the same as in the app (account «Блоки главной»; no pinned apps), the bottom «Профиль» tab becomes «Приложения» (all apps as icons like a regular launcher, or a list — a view toggle, device setting; «Профиль и настройки» and «Другой главный экран» come last, as icons or rows; app search, a «Недавние» row, a long-press menu with app shortcuts / app info / hide / uninstall, work-profile apps; the app recovers from a dead WebView renderer and falls back to another launcher after three failed starts); offline, network blocks are hidden as in the app. On BOOX the launcher's per-app auto-freeze (snowflake on its «Приложения» screen) disables the reader after a few idle minutes and Android drops the HOME role — the settings warn on Onyx devices. No server API, no web counterpart. Details in the reader's `AGENTS.md` («Домашний экран»)
- Android interface languages (app-only): the reader app is in Russian and English (Profile → Внешний вид → Язык, «Авто» = phone language: Russian for ru/uk/be/kk, English otherwise). Every app request sends `Accept-Language` = the app language (not the phone's), so server messages follow it — keep user-facing API errors localized through `t()`. Shared `public/position-sync.js` → `formatPositionDetail` words («стр. N из M», «раздел», «глава») follow `document.documentElement.lang` (`en` → «p. N of M», «section», «chapter»), used by the web and the app cross-device dialogs. No new API
