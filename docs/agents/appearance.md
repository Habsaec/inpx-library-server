# Appearance (palette, theme sets, background, effects, covers)

Part of the INPX Library Server agent spec. The rules every task must obey are in
[`AGENTS.md`](../../AGENTS.md); this file is the detailed reference of one subsystem.
Read it before changing that area and update it in the same commit as the code.

Scope: everything that decides how the library looks

---

## Theme API

- `GET /api/settings/ui` — public library chrome for Android: `siteName`, `logoUrl`, palettes, `radius`/`radiusPreset`/`radiusScale`, `shadows`/`shadowPreset`, `backgroundUrl`, `bgBlur`, `bgOverlayStrength`, `bgSize`, `bgPosition`, additive `headerUrl` / `hasHeader` / `hasCustomHeader` / `showHeader` / `showLogo` / `headerHeight` (80–640, default 180) / `headerPosition` (`center`/`top`/`bottom`) / `headerSize` (`contain`/`cover`, default `cover`; bundled `/header.png` is on by default — custom upload replaces it; Admin → Appearance can hide the header or logo), `surfaceOpacity` (0–100), `surfaceBlur` (0–24px), `coverFallbackUrl`, `coverFallbackLightUrl` (same URL when a custom placeholder is set; otherwise the dark and light bundled plates)

## Palette and theme sets

- Theme palette (`src/services/theme-engine.js`): the built-in surfaces (`#1a1612` / `#fff9f0`; old light default `#fffdf8` is an alias) resolve to the hand-tuned tokens of `styles.css`, so a changed accent or text color changes only that role (gold-tinted dark borders follow the accent). Auto links derive from the accent when one is set; every **auto** text / muted / link is nudged to ≥ 4.5:1 against the surface, its hover AND the page background (`ensureContrast(fg, [surface, surfaceHover, bg])`); the auto / preset **accent fill** only to 3:1 (`MIN_UI_CONTRAST`, WCAG 1.4.11 — 4.5 washed out bright presets such as amber). Derived ink (`paletteInk(palette)`, computed on the final palette after admin overrides): `accentText` = the accent as a text color, AA → CSS `--accent-text` (every `color: var(--accent)` rule reads `var(--accent-text, var(--accent))`); `accentOn` / `linkOn` = text on a solid accent / link fill (`onFillColor`) → `--accent-contrast` / `--link-contrast` (nav badge, active page link / tab, modal OK, checkmarks, primary buttons — no hard-coded `#fff` / `#1a1612` on a fill; the built-in light theme had `#1a1612` on `#8a6230` = 3.3:1). Theme CSS vars `--ui-theme-<mode>-accent-text|accent-on|link-on`; additive `accentText` / `accentOn` / `linkOn` in `appPalette*`. Nudges and hover shifts (`shiftLightness`) work in OKLCH lightness (hue kept, chroma cut only to fit sRGB); the auto accent / link hues from the surface are still generated in HSL. Dark vs light treatment of a surface = `isDarkSurface` (white text beats black in contrast, luminance ≈ 0.18 — the old `< 0.45` split gave mid-tone surfaces light text at 2–3:1), auto text aims at 7:1 so it stays above `muted`. A custom surface gets the built-in structure (`computeThemePalette`: page / shell / sidebar darker in dark mode, toward the text in light mode, translucent topbar, accent-tinted dark borders and fills; on a mid-tone surface a shade that would leave no AA ink goes the other way), not a flat «surface everywhere» look. Manual colors are kept and Admin → Appearance → Тема shows a contrast badge per role — the worst of surface / hover / page, threshold per role from `contrast.min` (4.5, accent 3); with a background picture and panel opacity < `GLASS_WARNING_OPACITY` (70) the card warns that the badges measure against the panel color (preview API returns `palettes.{dark,light}` with `contrast`). Only a custom surface, a background image or non-default panel sliders turn on glass panels (`usesPanelGlass`; stored defaults 88 / 0 do not count). `themeVersion` in `/api/settings/ui` is an opaque hash of the whole payload; `appPalette*.bg` is the page background (built-in `#14110e` / `#f3ebe0` by default). Web theme toggle cycles light → dark → «авто» (follows the OS light/dark; no `theme-preference` in localStorage), matching the Android «Авто». Android «Цвет: Сервер» applies the whole `appPalette*` (page, surfaces, text, muted, borders, links, accent), so keep every `appPalette` field meaningful
- Theme sets «Наборы оформления» (Admin → Appearance → tab «Наборы», `src/services/theme-sets.js`): a set = snapshot of the main look — theme colors (`ui_glass_*`, `ui_accent_*`, overlay colors, bg-palette), background picture + its sliders and panel glass, header picture + layout / `ui_show_header`, optionally («включая логотип и иконку», off by default) `ui_show_logo` + logo / favicons (`THEME_SET_KEYS`, `THEME_SET_LOGO_KEYS`, `THEME_SET_FILES`, `THEME_SET_LOGO_FILES`); fonts, radius / shadows, placeholder cover and manuscript stay shared. Settings `ui_theme_sets` (JSON list, ≤ 24, order = rotation order and calendar priority) + `ui_theme_schedule` (`{ mode: off|rotate|calendar, every, unit: hours|days, includeBase }`); pictures are flat files `data/ui/theme-set-<8 hex>-<file>` (copied with a fresh mtime → new `?v=`), so the portable backup carries sets with no change. Active set = pure function of the clock (`resolveThemeSetAt`: rotate = `(floor(server-local ms / period) + offset) % cycle`; schedule `offset` is re-anchored by `keepShownSet` / `saveThemeSchedule` so creating, deleting or moving a set, switching to rotation or changing the period never switches the look on the spot — the cycle length changes with the list and a new set used to take over the site the moment it was saved; day periods start at local midnight; calendar = first set whose `MM-DD` range holds today, ranges may wrap over New Year) — no timers, no writes, every cluster worker agrees. `ui-customization.js` reads every appearance setting through `themeSetSetting` (= `uiSetting`) and every file through `themeSetAssetPath`; a set file URL carries `&s=<id>`, a main-look file URL `&s=main` (`MAIN_LOOK_ASSET_ID`), and `/custom/ui/:asset?s=` serves exactly those bytes whatever is active (a cached URL never gets another set's picture; without `&s=main` the admin appearance page, which builds main-look URLs, was answered with the scheduled / previewed set's background, so a new main background never showed up there). A URL without `s` (old clients) follows the active look. Admin appearance routes (`/admin/appearance`, `/admin/settings/ui*`, `/api/admin/ui*`) run in `baseAppearanceMiddleware` (AsyncLocalStorage) and always show / edit the main look; the page shows an info banner while a set is on. Actions `POST /admin/settings/ui/sets/schedule|create|:id/update|replace|apply|up|down|delete` (web forms, redirect to `#sets`). **Sets are taken from the live preview, not from the saved look**: the «Сохранить предпросмотр как набор» fields (`setName` / `setFrom` / `setTo` / `setIncludeLogo`, empty name → «Набор N») and each set's «Записать предпросмотр» button belong to `#ui-main-form` and post it through `formaction` with `fromPreview=1`; the route turns the form into values with the real save code (`uiSettingsInputFromForm` → `saveUiSettings`) inside `dryRunSettings` (`src/db.js`: one transaction that is always rolled back, then the settings cache is dropped) and passes them as `settings` to `createThemeSetFromCurrent` / `replaceThemeSetFromCurrent` — the main look is not changed and «Сохранить» is not needed; pictures are always the uploaded files (uploads save at once). Without `fromPreview` (older forms) the saved main look is copied as before. A button with its own `data-confirm` asks first (`attachConfirmedButtonSubmits` in `app.js`). «Посмотреть» = `GET /admin/settings/ui/sets/:id/preview` → session cookie `inpx_ui_preview` (httpOnly) + redirect to `/`; `themeSetPreviewMiddleware` (after `attachSessionUser` in `server.js`) runs an admin's requests with that set (`runWithThemeSetPreview`, AsyncLocalStorage; `activeThemeSetOverride` prefers it over the schedule, never in the base-appearance context of the admin appearance pages; a stale id or a non-admin is ignored), `pageShell` shows a bar on top of the content (`renderThemeSetPreviewBanner`: «Применить» = POST `…/:id/apply`, «Закрыть предпросмотр» = `GET …/sets/preview-stop`, back to `#sets`); other visitors never see it. A set's own background / header are uploaded in its row straight into the set (`POST /api/admin/ui/sets/:id/upload?asset=background|header`, raw body like `/api/admin/ui/upload`; `saveUiAsset(asset, buf, { target })` writes `theme-set-<id>-<file>` and leaves the main look's palette alone; `setThemeSetFile` records it, a set with «тема из фона» gets its own `ui_bg_palette_*` via `bgPaletteFromFile`; `POST …/sets/:id/remove?asset=` drops it; `attachThemeSetPictures` in `app.js` updates the row in place, no reload) — uploading on the «Фон и эффекты» tab still writes the main look at once. Each set row also has the seasonal decoration checkboxes «Снег / Листопад / Гирлянда» (`decorForm=1` marker + `decorSnow|Leaves|Garland` → `decorFromFlags` → `updateThemeSet(id, { decor })`, stored as the set's `ui_decor`), saved with the row's «Сохранить». «Применить» copies a set into the main look (also clears the preview cookie; resyncs the Telegram avatar when the set carries the logo). The Telegram bot avatar reads `data/ui/logo.png` and is never switched by the schedule. Admin only — Android needs nothing: `/api/settings/ui` already returns the active set's palette / header / logo and a changed `themeVersion`

## Background layers

- Background layers (web, `public/styles.css` «Layers over a background image»): `body::before` picture (z -2) → `.main-wrap::after` content veil under the whole right column (z -2, panel glass × 0.75, follows «Прозрачность панелей») → `body::after` theme-tinted overlay (z -2, later in tree order) → decorative washes (z -1) → content. The picture is grown/scaled only while blurred (`backgroundLayoutToCssVars(size, position, blur)` → `--ui-bg-inset` / `--ui-bg-transform`); panel blur uses `--ui-panel-backdrop` (`none` at 0). `--bg` is transparent over a picture — use `var(--bg-solid, var(--bg))` where a real page color is needed. `prefers-reduced-transparency` / `prefers-contrast: more` force solid panels and veil. Admin slider «Видимость фона» = `bgOverlay` (0 hidden … 80 as is; default 32 → `bgOverlayStrength` 48). The Android app does not draw the server background picture

## Covers

- Cover tones (`src/services/cover-tones.js`, table `cover_tones (book_id, color, lqip)`, derived — skipped by the portable backup, dropped by `invalidateCoverThumbCaches`): the cover's most vivid color (`vividColor`: most chromatic mid-light pixels of a 12×18 copy; grey covers → sharp's histogram dominant) and an 8×12 WebP data URI placeholder (~170 chars). Computed only where the thumb bytes already exist — after a thumb is generated, on a memory / disk cache hit, and at list time from the server's disk thumb cache (`setCoverToneSource`; browsers keep 500 covers in the Service Worker and the app has its own cover cache, so those covers never come back) — one at a time through the shared sharp slots, queue ≤ 300; never generates a thumb, never scans the catalog. Additive `coverColor` / `coverLqip` on book payloads: `attachSeriesListsToBooks` (every list + `getBookById`), the `/api` `res.json` hook (`attachCoverTonesToBody`: `items[]`, `items[].items[]`, `items[].book` — list results are cached from before a tone existed) and `/api/books/:id/meta`. Web: `.cover-lqip` between the leather plate and the image (no CSS `filter`; removed when the image fails), card cache key carries `t0|1`, book page `has-cover-tone` wash (`--cover-tone`, centred on top ≤ 900 px, left of the cover above). Android: `BookCover` `placeholder` while loading, `BookDetailsSheet` wash (8-digit hex, not `color-mix`, for Chrome 83 WebViews); both validated (`coverTonesFromItem`)
- `GET /api/books/:id/cover-thumb` — additive `?hd=1`: twice the cover size setting (≤ 1200×1600), WebP q80; the Android reader asks for it in E-Ink mode (~300 ppi upscaled the 220×320 thumb). HD thumbs are kept only in the disk cache (`coverThumbCacheKey(id, true)` = `<id>#hd`, not in the 4000-entry memory cache); `invalidateCoverThumbCaches` drops both sizes. The web UI keeps the normal thumb

## Web chrome and effects

- Genre pattern tiles (web + Android): every genre row on `/genres` starts with a 28 px tile (`renderGenreSwatch` in `shared.js`, `.genre-swatch.gm-0…7` in `styles.css`: stripes, dots, grid, waves, zigzag, checker, rings, cross-hatch — CSS gradients only), motif and hue from `genreSwatchHash` of the genre's group (`getGenreGroup`), so one group shares a look. Android: the same motifs on the genre groups of the catalog (`lib/genrePattern.ts`, `genrePatternHash` = the same djb2-xor function, checked by a test on both sides)
- Empty states (web + Android): one small library scene — a shelf with three accent-tinted books, one leaning, and a round badge with the meaning of the screen. Web: `renderEmptyStateIllustration(kind)` inside `renderEmptyState({ kind })` (`books` default | `search` catalog / facet / search overview | `heart` favorites, bookmarks, following | `shelf` shelves, shelf page, collections), colors from the theme tokens, no fills in E-Ink. Android: `ui/EmptyState.tsx` draws the same scene (fill-opacity, not `color-mix`, for Chrome 83 WebViews) with the screen's lucide icon in the badge for `tone: 'default'`; error / offline / compact keep the plain icon
- Dim covers in the dark theme (web + Android): Admin → Appearance → Effects «Приглушать обложки в тёмной теме» (`ui_cover_dim`, default on; additive `coverDim` in `/api/settings/ui`). Web: a 10% black veil as the `background-color` of the existing `.cover::after` overlay (no `filter` on dozens of images), gone on hover / focus and with `data-ui-cover-dim="0"`; not on E-Ink. Android: `coverDim` (absent = on) → `html[data-cover-dim]`, `index.css` puts `filter: brightness(0.9)` on `.inpx-cover-img` (BookCover's image) in the dark theme
- Seasonal decoration (web only — the app does not draw the server background): Admin → Appearance → Effects «Сезонное украшение» — three checkboxes, any combination (`decorSnow` / `decorLeaves` / `decorGarland` → `decorFromFlags`; live preview sends the same flags). Setting `ui_decor` = comma list in canonical order (`UI_DECOR_PRESETS` snow, leaves, garland; old single values stay valid; the retired `drifts` — snow caps on cards, removed because they looked fake — is dropped by `normalizeDecor`), in `THEME_SET_KEYS`, so a New Year set can carry snow + garland. `<html data-ui-decor>` gets the list space-separated, CSS tests each with `[data-ui-decor~="…"]`. `public/decor.js` (loaded `defer` with `?v=`, listed in `computeStaticAssetVersion`): snow and leaves share one canvas in the fixed `.ui-decor` layer (z −1, under the content; both on → each ×0.7) — snow = fluffy irregular flake sprites (a few overlapping soft blobs, no geometric crystals) on depth layers with parallax, two-frequency turbulence per flake, gusting wind, ~5 % very near out-of-focus «bokeh» flakes (large, soft, fast), recycled flakes enter from the upwind side, a faint blue-grey shadow on the light theme; leaves = procedural maple (polar lobes, serration) / oak / elm outlines with mottling, darker rim and veins; ~65 % flutter (rock and glide, nearly stop at each end of the swing), the rest tumble; a leaf turned edge-on gets a dark silhouette drawn over it (pre-rendered `shade` sprite, no `ctx.filter`); garland = an SVG built for the window width and appended to `<body>` (`.ui-garland`: `position: fixed` at the very top of the window, full width over the sidebar and the header picture, z 101 — above the top bar (90) and the fixed sidebar (100), under menus / toasts / modals (1000); `pointer-events: none`, so bulbs over the top-bar buttons never block a click; rebuilt by a `ResizeObserver` on `<html>` and on resize): a twisted two-strand wire sagging between clips every ~200 px, a C9 bulb every ~34 px with slight jitter in spacing, size and tilt (hangs mostly straight down) — metal socket (linear gradient), glass lit from inside (radial gradient: near-white core low in the bulb → saturated edge; classic, not neon colours) and a faint shine, a soft halo (radial gradient, no blur filter). Lights are steady — nothing sways; ~15 % of bulbs (`.ui-garland-tw`, per-bulb `--t` 6–12 s / `--d`) dim slowly now and then (none with reduced motion; tighter halo on the light theme). Canvas: sprites drawn once, count by screen area, DPR ≤ 1.5, paused in a hidden tab (no rAF there — check it in a visible window), idle while no effect is on (MutationObserver on `data-ui-decor` / `data-theme` / `data-eink`), no canvas with `prefers-reduced-motion`; nothing at all in E-Ink mode
- Author cover fan (web + Android): an author without a portrait gets up to five of his covers fanned out in the page hero instead of the leather plate with the name (`renderAuthorCoverFan` in `src/templates/library.js`, `.author-cover-fan` in `styles.css`; books with a known cover tone first — the server has seen a real cover —, tone + placeholder as the backdrop, a failing thumb removes itself; one cover nearly fills the box, five leave room for the tilt). Android: `AuthorPortrait` `fanBooks` — three small covers in the 80 px header slot instead of the initials when the grouped endpoint says `hasPortrait: false` (`authorFanBooks` in `CatalogDrilldownPanel`). The `/api` tone hook also fills the grouped shape (`standaloneBooks`, `books`, `series[].books`)
- Page transitions (web only; the app has its own screens): cross-document View Transitions (`@view-transition { navigation: auto }` in `styles.css`, Chrome / Edge 126+, ignored elsewhere). The book page cover is always `view-transition-name: book-cover` (not on series / author heroes); the head boot script (`renderThemeBootScript`, must run before the first render for `pagereveal`) names only the list card of the book being opened (`pageswap`) or returned to (`pagereveal`, `navigation.activation.from`) and clears the name afterwards — two elements with one name abort the transition. Admin → Appearance → Effects «Плавные переходы между страницами» (`ui_page_transitions`, default on) → `data-ui-transitions="0"` → `skipTransition()`; also skipped in E-Ink mode (`data-eink="1"`) and off with `prefers-reduced-motion`. Chrome runs no transition in a hidden tab (the desktop app's browser pane reports `hidden`), so check the motion in a normal browser window
- 3D book covers (web only): catalog cards, home carousel and book page turn on mouse hover (the home quote cover / author portraits stay flat; hero / book page only while the pointer is over the cover itself: stable `.book-3d` wrapper catches hover, inner `.book-3d-body` turns) (flat at rest; off for touch / `prefers-reduced-motion`). At rest a cover is plain 2D — no `preserve-3d`, no `translateZ`, the page edge / back plate pseudo-elements are `display: none` — because a page of covers each holding a 3D context was hundreds of GPU layers and made every page sluggish on weaker GPUs or without hardware acceleration; only the hovered book switches to 3D, and it stays 3D until it has turned back (`transform-style` / `display` / the children's `translateZ` change after the 0.6 s turn via `transition-behavior: allow-discrete` + delay, the back plate fades in with `@starting-style`). Admin → Appearance → Effects → «3D-обложки книг» (`ui_book_3d`, default on) sets `data-ui-book3d="0"` on `<html>`, every rule in the «3D book covers» block of `public/styles.css` is gated by `html:not([data-ui-book3d="0"])`. Not part of `/api/settings/ui` (Android reader doesn't use it)
- Home quote cover = the quote author's "book": author name + link to their books, portrait from `GET /api/authors/portrait?name=` when present (blurs out with the quote on rotation). The endpoint falls back to word-order-independent `listAuthors` matching when the exact name misses («Александр Пушкин» → «Пушкин Александр Сергеевич»)
- Web home, catalog, search, novinki and recommendations support covers or `?view=list` (compact list rows). Home shelves («Новинки», recommendations, pinned shelves) share one batch-select scope. The home toggle is `/?view=list|grid` for guests; signed-in users `POST /profile/home-view` (`view=list|grid`, CSRF), which saves `users.ui_home_view` and keeps the catalog preference. The catalog toggle does the same for `users.ui_catalog_view` via `POST /profile/catalog-view` (`view`, CSRF, `next` back to the current `/catalog` filters without `view`) and leaves the home preference unchanged
