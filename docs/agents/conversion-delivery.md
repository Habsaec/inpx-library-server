# Conversion and delivery (fbc, formats, e-mail)

Part of the INPX Library Server agent spec. The rules every task must obey are in
[`AGENTS.md`](../../AGENTS.md); this file is the detailed reference of one subsystem.
Read it before changing that area and update it in the same commit as the code.

Scope: turning a catalog book into a downloadable or mailed file

---

## Rules

| Rule | Meaning |
|------|---------|
| fb2cng conversion options | Admin → «Конвертация» (own page `GET /admin/conversion`, sidebar item after «Контент»). Cards in this order: «Скачивание» (download formats `disabled_download_formats`, file name style `download_filename_style`, WebP in FB2 `fb2_webp_images` — moved from «Контент»; own form `POST /admin/conversion/delivery`, `renderAdminDeliveryCard`), «Конвертер fbc», «Настройки конвертации», «Предпросмотр». «Контент» keeps languages, genres, deleted books («Видимость книг»), collections and a link to the conversion page; `POST /admin/content` no longer touches the download settings (absent checkboxes there would have disabled every format). `POST /admin/conversion`, `src/fb2cng-options.js`): whitelisted bool / enum / clamped numbers (footnotes, annotation, TOC page/type, page map, open from cover, soft hyphens, drop caps, old-FB2 text fixes, image quality/scale/screen/cover). Sparse JSON setting `fb2cng_options` (differences from the shipped `converter/fb2cng.yaml`); at run time the base YAML (`FB2CNG_CONFIG_PATH` or the shipped file) is patched line-wise into `data/converter/fb2cng-<hash>.yaml` (`fbc` does NOT merge several `-c`, the last wins). Saved only after `fbc dumpconfig` accepts it (unknown field / out-of-range value → error, nothing stored; screen min 600). The hash is part of the conversion cache key and the lock key, so old converted files are bypassed. FB2 / FB2.ZIP unaffected. fbc is pinned to **v2.1.1** (`install.cmd` with SHA-256 per arch, `install.sh`, `Dockerfile`; an existing `converter/fbc` is never replaced by the installers — admins update from the panel or rebuild the image); the shipped `fb2cng.yaml` must not contain keys removed in 1.9 / 2.0 (`footnotes.backlinks` → `backlink_template`, `document.images.markdown` → `document.markdown.images`: an unknown key makes fbc reject the whole file). Options may carry `pathSince` (the key moved in a newer fbc — `md_images`) and `valuesSince` (an enum value a newer fbc added — cover `fill` 2.1); `buildFb2cngConfigText(…, { version })` / `diffFb2cngOptions(full, version)` pick keys, paths and values for THAT version (default = the installed binary), and the panel update validates the saved settings with the candidate's version (`installLatestFbc({ validateConfigFor })` → `writeCurrentConfigForCheck(null, version)`). Never pass `isFb2cngOptionSupported` / `fb2cngSupports` straight to `Array#filter` — the index becomes the version. `getFb2cngVersion()` runs `fbc --version` once; options carry `since` and are hidden / not written for an older binary, the extra output formats `kepub3`, `pdf`, `txt`, `md` (`FB2_CONVERTIBLE_FORMATS`, FB2 books only, MIME/extension in `conversion.js`) need fbc ≥ 1.6, `azw3` (native KF8, label `AZW3`, `--ebook` like KFX / AZW8, OPDS MIME `application/x-mobipocket-ebook`) needs fbc ≥ 2.0 (`getFb2cngConvertibleFormats`); the format code `azw3` is shared with native AZW3 books (Calibre / folders), so disabling it in «Скачивание» also hides their downloads — the same as `pdf` / `txt`. The fbc version is part of the conversion cache key. Also covered: KFX/AZW8 compression, AZW3 compression (`document.azw3.compression` none / standard / huffdic, fbc 2.0; `document.azw3.apnx` is not offered — it writes a sidecar / `.sdr` folder a single download cannot carry), fbc 2.1 image options (`fit_to_screen`, `baseline_jpeg`, `grayscale` none / luma, cover `fill`), PDF page frame, Markdown images (placeholder / embedded; `external` is not offered — it writes a directory), SVG rasterization, raster format, screen dpi, cover `fit`. Free-text options (all validated by fbc before saving): Go templates `title_template` / `creator_name_template` / toc `authors_template` (textarea prefilled with the base value; an unchanged text = no override; written only as a `|2-` block scalar, ≤ 4000 chars, control chars stripped), own CSS (≤ 200 000 chars, stored in the option JSON, written to `data/converter/css-<hash>.css`, the config gets `stylesheet_path` = that path — admin never types a server path; it REPLACES the built-in CSS), vignette width (`vg_width`: full / 75 / 50 / 33 % / original size — fbc's own CSS has `img.image-vignette { width: 100% }`, which blows an uploaded ornament up to the page width; there is no YAML key, so it is a CSS rule appended to the stylesheet). fbc's built-in stylesheet is taken from a real sample conversion once per fbc version (`ensureFb2cngBuiltinCss` → `data/converter/builtin-<version>.css`); the «Свой CSS» textarea is prefilled with it (unchanged text = no override) and extra rules are appended to own CSS or to the built-in one — never written alone, because `stylesheet_path` replaces fbc's stylesheet. Preview pages get reader-like margins (injected into the preview response only). Corrections of fbc's stylesheet (`fb2cngFixCss`, only when the feature is on; placed after the built-in CSS but before own CSS, so the admin's rules still win; `FB2CNG_CSS_FIX_VERSION` is part of the options hash — bump it when they change so configs and converted books are rebuilt): drop cap `line-height: 0.8` (with fbc's `1` the big letter sat below the first line) and vignettes `display: block; margin: auto`. **fbc's PDF engine** places a vignette with an explicit width at the left edge (it ignores `text-align`, `margin: auto`, the parent's alignment and per-position descendant selectors, and resolves percentage margins against something tiny), so for PDF (`@media fbc-pdf`) the vignette gets `width: 100%` plus side margins in pt computed from the text column = `screen.width / dpi × 72 − 2 × 24 pt` (fbc's fixed page margins); «original size» uses the widest uploaded vignette (`imagePixelWidth` reads PNG / GIF / JPEG / WebP headers). Fonts (group «Шрифты», CSS only, roles text / headings / drop cap): family default / serif / sans-serif / monospace / own font, plus size (text %, headings % on the title containers, drop cap em). Own fonts: raw TTF / OTF only (sniffed: `00010000` / `true` / `OTTO`; PDF cannot use WOFF or collections), ≤ 20 MB, `POST /admin/conversion/font` with an `application/octet-stream` body (`express.raw` on that route) and `X-File-Name`, stored as `data/converter/fonts/<sha1-16>.<ext>` + `<hash>.json` (original name), slot value `font:<name>`; text and headings take regular / bold / italic / bold-italic files (PDF never fakes bold or italic; a heading font without a bold face gets `font-weight: normal`), the drop cap one file. CSS: `@font-face` "INPX Text" / "INPX Headings" / "INPX Dropcap" with `url("fonts/<file>")`, a bare `body { font-family }` (KFX turns it into the document default font), the heading selector list incl. every `*-title-header*` class, `p.has-dropcap .dropcap`. **fbc resolves stylesheet `url()` against its working directory, not the stylesheet's (contrary to its docs)**: `runConverter` runs fbc from the generated config's folder, and `materializeCssSync` copies the used fonts into `<dir>/fonts/` when the stylesheet is written outside `data/converter` (check / preview temp folders). Unreferenced font files are removed an hour after a save, like vignette images. Vignettes (8 slots: `off` / `builtin` / own image — the file input posts base64 JSON to `POST /admin/conversion/vignette` (2 MB JSON parser in `server.js`), type sniffed from bytes (PNG / JPEG / GIF / WebP ≤ 1 MB), stored as `data/converter/vignettes/<sha1-16>.<ext>`, the slot value is the token `file:<name>`, the config gets the absolute path built by the server; unreferenced files are deleted an hour after a save / reset). `fbc dumpconfig` does NOT parse Go templates and `convert` survives a broken one with a WARN, so `validateFb2cngOptions` also converts a tiny sample FB2 to EPUB2 and fails on any WARN/ERROR line mentioning `template`. The fbc `output_name_template` is not offered: the downloaded name comes from Admin → Content «Имя файла» (`matchedName` in `convertFb2Book` takes whatever fbc wrote). **fbc update from the admin panel** (`src/fb2cng-binary.js`, `POST /admin/conversion/fbc-check|fbc-update|fbc-reset`): binary priority `FB2CNG_PATH` (update disabled) → `data/converter/bin/fbc[.exe]` → shipped `converter/fbc`; `getFb2cngBinaryPath()` is used for every spawn / version probe. Latest release from the GitHub REST API (60 req/h per IP, so a 403/429 falls back to the `/releases/latest` redirect + `expanded_assets` page for the asset SHA-256); no digest = refuse; the zip is hashed while downloading (≤ 200 MB), only the `fbc[.exe]` entry is extracted, the candidate must print the same version and accept the current settings (`dumpconfig`), then the old file is renamed aside and the new one copied in (Windows can't overwrite a running exe, a rename works). **Preview** (`src/fb2cng-preview.js`, `POST /admin/conversion/preview` JSON `{ fields, book, format }`, `GET /admin/conversion/preview/:token/*`): converts a catalog FB2 book (link or id; a non-FB2 book is refused with an explanation — fbc reads FB2 only, other formats are never converted) or a built-in sample to **any format fbc offers** (`getFb2cngConvertibleFormats()`: EPUB / EPUB3 / KEPUB / KEPUB3 page view; PDF in the browser's PDF viewer in a frame without `sandbox`; TXT / Markdown as text; KFX / AZW8 / AZW3 cannot be drawn by a browser, so the real file is offered as a download and the page view is the EPUB3 build of the same settings, labelled as an approximation) with the form's current, unsaved settings (`convertForPreview` in `conversion.js`, same converter slots, no cache), keeps the unzipped EPUB in memory for 15 min (≤ 4 previews, ≤ 60 MB) and serves its files under their real MIME types into an `iframe sandbox="allow-same-origin"`; responses carry CSP `sandbox` so book scripts never run, token + admin session required. Nothing is saved. Network only on an admin button press; «Вернуть встроенный» deletes the installed file. Admin only — Android needs nothing (AZW3 reaches the app only as an extra `downloadFormats` code; its «Формат скачивания» stays on the EPUB family, reader AGENTS.md) |

## Delivery

- E-mail to an e-reader (`/api/send-to-ereader/:id`, `/batch`) names the attachment by the title (`EMAIL_FILENAME_STYLE` = `title`, `resolveDownload(…, { filenameStyle })`), whatever Admin → Конвертация → Скачивание says: Kindle shows the attachment name as the book title. Downloads, ZIP and Telegram keep the admin style
- Download format `fb2zip` (label `FB2.ZIP`, file `*.fb2.zip`, `application/zip`): the delivered FB2 (WebP mode, sidecar images applied) zipped as a single entry in memory (`resolveDownload`); offered for every FB2 book without fb2cng, admin can disable it like other formats. Additive entry in `downloadFormats`; OPDS links unchanged. The web e-mail dialog remembers the last format in `localStorage['ereader-format']`
