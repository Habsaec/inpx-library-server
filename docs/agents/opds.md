# OPDS 1.x / 2

Part of the INPX Library Server agent spec. The rules every task must obey are in
[`AGENTS.md`](../../AGENTS.md); this file is the detailed reference of one subsystem.
Read it before changing that area and update it in the same commit as the code.

Scope: every OPDS feed, counter and entry in `src/routes/opds*.js`

## Rules

| Rule | Meaning |
|------|---------|
| OPDS personal feeds | Under «Моя библиотека» (`/opds/user`, v2 `/opds/v2/user`): `bookmarks` (favorite books), `shelves[/:id]`, `smart-shelves[/:id]` (v2 got it too), `favorite-authors`, `favorite-series`, and additive `want` («Хочу прочитать»), `following` («Новое у любимых»; opening it does NOT mark the list seen — an OPDS client may poll), `recommended` (a pool still being built answers an empty feed). ## Feeds, counters, progress

- OPDS progress icons (`src/opds-progress.js`): OPDS v1 acquisition titles of started books get a prefix ◔ (≤25%) ◑ (≤50%) ◕ (>50%) ⬤ (read or ≥99%); sources `reading_positions`, `read_books`, KOSync percentage (max wins). Unstarted books are untouched, no opt-out toggle, OPDS v2 JSON unchanged
- OPDS «все книги автора / серии» (`opdsBookRelated` in `src/templates/opds.js`): every OPDS v1 book entry (lists and `/opds/book`) has `rel="related"` acquisition links «Все книги автора X» → `/opds/author?author==<name>` (≤ 5 authors) and «Все книги серии «S»» → `/opds/series?series==<name>` (`seriesList`, else `books.series`; ≤ 3), like flibusta.is/opds; OPDS v2 `/opds/v2/book/:id` gets the same `related` links to `/opds/v2/authors?prefix==…` / `/opds/v2/series?prefix==…`. Book payloads carry the raw INPX author spelling (`Кубатиев,Алан,Кайсанбекович`), `authors.name` is the lower-case key, so the author feeds pass `=<name>` through `resolveAuthorName` (`opdsAuthorKey`) before `getAuthorBooksOpds`. Server only — Android does not use OPDS
- OPDS counters (v1 + v2) match what the entry opens: author rows (prefix lists, genre lists, search, favorites) show one row per author key (`preferredAuthorRowSql`) and the book count with every same-key alias (`authorAliasBookCount` = `facetEntityBookCount`; `authors.book_count` is one spelling — 47 listed, 53 in the feed); the author feed takes its series groups from `book_series` (`getAuthorSeriesGroupsOpds`, the membership the author + series feed reads, not the `books.series` text) and pages the books outside series 100 at a time (`getAuthorStandaloneBooksOpds`, `?page=` + `next`); the series feed pages too (`getSeriesBooksOpds(name, { limit, offset })` + `countSeriesBooksOpds`) — both used to stop at 500 books. Genre group totals = distinct books (`getGenreGroupBookCountsAsync`: one `book_genres` scan on the query worker, ~2–5 s cold, stale-while-revalidate 30 min per catalog generation; falls back to the old sum on a worker error). Smart shelves (`listSmartShelves(…, { withPreview: true })`), favorite authors / series and v2 shelves (`count`, not `properties`) got counts; a shelf counts only visible books (`active_books`, like its feed). Server only — Android does not use OPDS
- OPDS feeds and entries (v1 + v2; shared code `src/opds-common.js` — acquisitions, per-page book meta, paging, `<updated>` stamp — and `src/opds-feeds.js` — feed data): **all download formats** per book (`opdsAcquisitions`: the old FB2+ZIP default and EPUB links stay first for clients that remember them, then every format `getAvailableDownloadFormats` offers — EPUB3, KEPUB/KEPUB3 as `application/kepub+zip`, KFX/AZW8 as `application/vnd.amazon.ebook`, PDF, TXT, Markdown, plain FB2 — disabled formats left out, then Calibre extra files; `length` on a file served as is). Book entries carry `dc:issued` (FB2 publish year from `book_details_cache`, else the INPX date year) and `dc:identifier urn:isbn:…` (v2 `published` / `identifier`), loaded for the whole page in one query (`loadOpdsBookMeta`). Catalog root: **«Новинки»** `/opds/new` (`/opds/v2/new`; `getLibraryView('recent')`, profile languages, shared stale-while-revalidate cache) with OPDS 1.2 **facets** sort (`recent|title|rating`) and language (`?sort=`, `?lang=`; v2 `facets`), **«Подборки»** `/opds/collections[/:slug]` (shown when an enabled collection has found books, memo 5 min). «Моя библиотека»: **«Читаю»** `/opds/user/continue`, **«Прочитано»** `/opds/user/read`, **«Мои оценки»** `/opds/user/rated` (same `getLibraryView` lists as the site; v2 too). Book feeds page with `first/previous/next/last` links + `opensearch:totalResults|itemsPerPage|startIndex` (`opdsPaging`; v2 `numberOfItems` / `itemsPerPage` / `currentPage`). Navigation entries get pictures: a series → cover of its first volume (`withSeriesCovers`, memo 30 min, ≤ 150 ms per page, pages of ≤ 200 entries), a collection → its first found book, an author → `/api/authors/portrait` when an enabled source has Flibusta sidecars (that route now accepts OPDS Basic auth via `requireBrowseOrOpds`). Feed `<updated>` is rounded to 5 minutes (`opdsUpdatedStamp`): a per-second stamp changed every body, so the weak ETag never matched and clients never got a 304. `test/opds-routes-smoke.test.js` boots the OPDS routes on the test DB and checks every feed (status, well-formed XML / JSON, 304). Server only — Android does not use OPDS
